Client outline

Happenings

One agenda page, then three URLs a visitor clicks through. Desktop and phone are the same pages — resize the browser.

Click-through pages

  1. Listing — browse, filter, tap a card (tap happens here; not a separate screen).
    happenings-listing.html
  2. Ticketed event — Gameday Kickoff: Get Tickets → date/qty → confirmation.
    happenings-transactional.html
  3. RSVP event — Film Night: Save My Spot → you’re on the list.
    happenings-rsvp.html
  4. Hero height options — short / medium / tall + listing reference.
    happenings-hero-options.html

Visitor flow

Listing → optional filter (same page, fewer cards) → tap a card on the listing → ticketed or RSVP detail (whichever the event was published as) → conversion → confirmation → more upcoming events → back to listing.

Filters only change which cards show. They do not pick ticketed vs RSVP — that is already set on each event when an editor publishes it.

Listing filters (6)

FilterWhat it doesTicketed vs RSVP
AllFull gridMix of both
UpcomingFuture eventsMix
Free / RSVPFree-with-RSVP eventsAll RSVP pages
TicketedPaid / checkout eventsAll ticketed pages
ExhibitionsExhibition programmingMix (e.g. paid exhibition + free talk)
CommunityCommunity programmingUsually RSVP (not always in Free / RSVP filter)

Desktop uses chip buttons. Phone (≤900px) uses a styled Filter dropdown with the same six options. Filters still only change which cards show.

Every event still uses exactly one detail path: Get Tickets or Save My Spot. There is no third visitor path.

Editor decisions (CMS — not visitor-facing)

Set once when the event is published in Umbraco:

  • Template: Ticketed (transactional) or RSVP — determines which detail page and CTA.
  • Categories: one or more listing filters above (managed in CMS).
  • Ticketed options: Ventrata on/off, sidebar, Add to Calendar, image hero minimum height (short / medium / tall — actual height grows with title, subtitle, meta, and CTAs).
  • RSVP options: native form, form embed, or Facebook Event — one conversion module only, never two. Image hero minimum height (short / medium / tall — content sets actual height).

Phone vs desktop is the browser, not separate mocks or URLs.
